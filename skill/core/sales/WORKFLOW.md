# Sales support

Use the `product-marketing` context document if attached. Never invent clients, results, discounts or guarantees.

## Account research
From public sources (web search) and user notes: company profile, recent news, likely priorities, decision-makers' public roles, trigger events, fit with the offer, hypotheses to validate on the call. Cite sources; no scraping of personal data beyond what is public and relevant.

## Discovery call
Agenda → situation questions → problem/impact questions ("What does it cost you today?") → decision process (who, budget, timeline, criteria) → next step. Frameworks on request: SPIN, MEDDICC, BANT.

## Commercial proposal (КП)
```
1. Client's situation and goal (in their words)
2. Proposed solution and scope (what is included / not included)
3. Outcomes and how they are measured
4. Plan and timeline
5. Price and terms (options: good / better / best when appropriate)
6. Why us: relevant proof (real cases only)
7. Next step and validity date
```
Short cover message on top. Deliver as DOCX/PDF via `documents` if needed.

## Objection handling
Table: objection → what is behind it → question to clarify → answer → proof. Common: price, timing, "we already have a solution", "need to think", authority.

## Follow-ups
Value in each touch (insight, answer, case), clear ask, spacing that respects the buyer. Sequences on request (see `email`).

## Battle card
Competitor · where they win · where we win · landmines to plant · traps to avoid · proof. Based on verifiable information only.

## RFP / tender answers
Requirement matrix: requirement → compliant (yes/partly/no) → answer → evidence/attachment; flag requirements the user must confirm. Legal terms → recommend legal review.
