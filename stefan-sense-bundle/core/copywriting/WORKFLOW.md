# Copywriting

Goal: copy that a specific reader understands instantly, believes, and acts on. Clear beats clever.

## 1. Context first
If the user has a brand/product context file (see `product-marketing`) in the chat or project, read it and ask only for what is missing. Otherwise collect (max 4 questions, skip what is known):
- **Page/asset and the ONE action** (buy, sign up, book a call, download).
- **Reader**: who, which problem, which objections, their own words for the problem.
- **Offer**: what it is, the difference vs alternatives, the outcome, proof (numbers, reviews, cases, logos).
- **Traffic context**: where readers come from and what they already know.

## 2. Principles
- Benefits over features: feature → so that → outcome for the reader.
- Specific over vague: "Weekly reporting in 15 minutes instead of 4 hours" beats "save time" — but only with real numbers from the user.
- Customer language over company language; mirror reviews, interviews, support tickets.
- One idea per section; each section moves the argument forward.
- Honest over sensational: no invented stats, testimonials, scarcity or guarantees. Missing proof → `[NEED: …]`.
- Swap test: if a line would work unchanged on a competitor's page, rewrite it or flag `[NEED: differentiator]`.

## 3. Page skeleton (adapt; not every page needs every block)
1. **Hero**: headline (core value, specific) + subheadline (who/how, 1–2 sentences) + primary CTA (verb + what they get: "Start my free trial", «Получить расчёт»).
2. Social proof (only real).
3. Problem / pain in the reader's words.
4. Solution and 3–5 benefits.
5. How it works (3–4 steps).
6. Objections: FAQ, comparisons, guarantees (real ones).
7. Final CTA with recap and risk reversal.
Page specifics: homepage — several intents, broad value; landing page — one message, one CTA, match the ad; pricing — help choose, highlight the recommended plan; feature — feature → benefit → use case.

## 4. Style
Simple words, active voice, confident (cut "very", "really", "almost"), no exclamation marks, no buzzwords (seamless, robust, unlock, streamline, innovative, «уникальный», «инновационный»). No AI tells: no "It's not X, it's Y", no negation lists, no "The result? …", no stock openers, no em dashes in short copy. Full blacklist: `references/ai-tells.md`.

## 5. Output
1. Copy organized by section (headline, subheadline, CTA, section headers and body).
2. 2–3 alternatives for the headline and CTA, each with a one-line rationale.
3. Short annotations for key choices (which principle, which proof).
4. Meta title + meta description if it is a web page.
5. `[NEED: …]` list of missing proof.
Then offer an `edit` pass or an A/B test plan (library `ab-test-setup`).
